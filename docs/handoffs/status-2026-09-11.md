## Deviations from written handoffs (so nobody rediscovers these the hard way)

- The AI-insights-chart handoff (`docs/handoffs/ai-insights-chart.md`) assumed a prior
  "6→11 scheme expansion + scheme discovery" handoff had already been applied to this
  repo. It hadn't — that handoff was never actually delivered. Applying the chart
  handoff's files verbatim would have broken the build (`scheme_match.py` importing a
  `SCHEME_TYPE_MARKET_ACCESS` constant that doesn't exist in `scheme_facts.py`;
  `SchemeMatchPage.jsx` importing `fetchSchemeDiscovery` from a file that doesn't exist).
  Applied with three adaptations instead (full detail in commit `8035578`'s message):
  - Dropped the `SCHEME_TYPE_MARKET_ACCESS` import/branch (falls through to the existing
    generic fallback).
  - Left the scheme-discovery UI/state entirely out of `SchemeMatchPage.jsx`, and the
    unused `SchemeDiscoveryRequest`/`Response` Pydantic models out of `schemas.py` — that
    feature doesn't exist in this repo, so wiring in dead references to it would be
    actively misleading.
  - `tests/test_new_schemes.py` doesn't exist here; its one test was appended to the
    existing `tests/test_scheme_match.py` instead.
  - **If a teammate has the actual "6→11 scheme expansion" handoff doc**, applying it
    properly (adding the 5 new schemes to `scheme_facts.py`, `scheme_discovery.py`, the
    frontend API client, etc.) would let all of the above be un-adapted back to the
    handoff's original form.
- An earlier session's Docker Compose fix: `docker-compose.yml`'s `advisory-llm` service
  bind-mounts `./services/advisory-llm:/app` for dev hot-reload, which **shadows** the
  models trained into the image at Docker build time. If `GET /debug/status` ever reports
  either `*_model_available: false` after a plain `docker compose up`, that's why —
  regenerate the models onto the host directly (commands now in
  `services/advisory-llm/README.md`) rather than assuming the build is broken.
